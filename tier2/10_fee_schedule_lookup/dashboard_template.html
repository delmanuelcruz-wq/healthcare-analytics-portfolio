The matching rule

A match needs the same code, the same claim type and a service date inside the rate's effective dates (inclusive). Buckets are assigned in this order, so each request lands in exactly one.

1Duplicate requestSame code, claim type and date as an earlier request. The original keeps its bucket.
2Matched / Zero-payAll three keys match. $0.00 is a real (non-covered, mock) rate.
3No matchThe code is not on the schedule at all.
4Wrong claim typeThe code exists, but only under another claim type.
5Out of date rangeCode and claim type exist, but no rate was in force on the service date.
