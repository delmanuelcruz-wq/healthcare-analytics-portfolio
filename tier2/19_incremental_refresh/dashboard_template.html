Incremental refresh with an audit trail

Daily appointment-change files loaded with an idempotent upsert, so re-sent, late and out-of-order files cannot double count or move a visit backwards - then completed appointments reported against monthly goals, with late corrections made visible.

Initial load to Aug 31 + daily drops Sep 1 - Oct 24, 2026Data as of Seed

How each file is loaded

1 · Daily dropEvery status change recorded yesterday and today (a deliberate two-day overlap).
2 · StageFile rows land in a staging table inside one transaction per file.
3 · HistoryINSERT OR IGNORE on the natural key (appt_key, changed_at).
4 · Current stateUpsert one row per appointment, only WHERE new.changed_at > current.changed_at.
5 · AuditOne row per delivery: rows read, inserted, ignored, stale, late, restated.
6 · Goals vs actualsCompleted appointments by site and month against the 2026 goals.
